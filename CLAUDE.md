## Stack and commands

TypeScript + Node for the simulation and headless CLI; Babylon.js for rendering (web build).

- build: `npm install && npm run build` (esbuild: `src/headless.ts` -> `dist/headless.js`, `src/web/main.ts` + `index.html` -> `dist/web`); typecheck: `npm run typecheck`
- run: `npm start` = `node scripts/serve.mjs` serves `dist/web` on :8080 (`PORT` env or `--port`; picks the next port when busy) and the leaderboard API (`data/leaderboard.json`, `LEADERBOARD_PATH` env); `node scripts/serve.mjs --export-leaderboard out.json` exports it. `scripts/server.mjs` holds the server and leaderboard logic.
- bench: `npm run bench` = `node scripts/bench.mjs --seed 42 --duration 30 --out bench.json` (Chrome via puppeteer-core; the page is `?bench=1&seed=&duration=` and uses a MessageChannel + gl.finish loop instead of requestAnimationFrame, see phase4-assumptions D2); soak: `npm run soak` = `node dist/soak.js --seed 7 --nights 10 --out soak.json` (`src/soak.ts`). `src/sim/bench.ts` builds the benchmark scenario (`bench: true` switches gameplay off).
- package: `npm run package` builds `release/dao-den-long-v1.0.0.zip` (static web + Node server) for the GitHub Release.
- headless: `node dist/headless.js --seed <n> --night 1|2|3 --ticks <n> --out <file.jsonl> [--scenario f] [--inputs f] [--snapshot-every n]`
- tests: `npm test` (build, then `tests/run.mjs` over `tests/cases/cases.json`, which is GENERATED by `python tests/gen_cases.py` (edit the generator, not the JSON) + determinism for 3 nights + full-night timing <= 30 s; writes `docs/proof/phase4/`)
- e2e: `npm run e2e` drives the real web game in headless Chrome via puppeteer-core (needs Chrome; `CHROME_PATH` to override), real key presses, FPS on the real GPU; writes `docs/proof/phase4/e2e-results.md` and `screens/e2e-*.png`. The game exposes a read-only `window.__game` handle for it (`sim`, `yaw`, `flow`, `night`, `total`).
- dev/demo URL: `?autostart&night=N&seed=S&scenario=<urlencoded scenario JSON>` skips menu and intro (same scenario format as headless).
- Layout: `src/sim/` is pure logic with no DOM or Babylon imports, shared by the game and `src/headless.ts`: `sim.ts` (tick order from the ticket), `maps.ts` (the three Nights: height field, lanterns, spawn points, pads), `scenario.ts` (input validation, exit code 2), `tuning.ts` (`TUNING` imported from `game.contract.json`, plus engine constants `K`). `src/web/` is rendering, HUD, screens, settings (localStorage) and synthesised audio (`audio.ts`); it only reads sim state.
- Determinism: separate seeded RNG streams per purpose (`stream(seed, salt)`); never use `Math.random` or wall-clock time in `src/sim`.
- Skill: `.claude/skills/headless-scenario/SKILL.md` explains how to add a hand-computed test case.
- Hook: `.claude/settings.json` has a Stop hook that runs `npm test` (with `DDL_PROOF_DIR` pointing to a temp folder so the committed proof is not rewritten) and blocks finishing (exit 2) while headless tests are red. CI: `.github/workflows/test.yml` runs typecheck + `npm test` on every push. `DDL_PROOF_DIR` also redirects `npm run e2e` output.

## Lessons (update when the agent repeats a mistake)

- Expected values in `tests/cases/cases.json` are hand-computed from tuning and tick order; never copy them from game output. After a change, break a tuning value on purpose and confirm a case goes red.
- Each phase writes its own proof folder (`docs/proof/phaseN/`; the proof path is hard-coded in `tests/run.mjs` and `tests/e2e.mjs`: change it when starting a new phase, or the old proof gets overwritten); never regenerate or edit an earlier phase's proof, it must match its tag.
- The Edit/Write tools refuse to overwrite a file that was not read in the same session: Read first.
- Do not kill processes broadly (`taskkill /IM node.exe`); kill the PID that owns the port.
- Lit lanterns lose 1 fuel unit per tick before the interact step, so a lit lantern is never full when interacted with after tick 1; tests that interact with a lit lantern must expect a refuel.
- Fuel is stored as integer units of 1/60 (`fuelU`); only round when writing snapshots/events (1 decimal).
- UI text must stay >= 1rem (18 px): all CSS uses rem and an e2e test scans computed font sizes. Shades are drawn with thin instances (`putInstance`/`syncShades`), never one mesh per shade (200 are drawn in the benchmark).
- Do not `taskkill` by image name; there are other node/Chrome processes. Chrome with an unlocked requestAnimationFrame stalls ~200 ms every ~0.5 s; do not benchmark through rAF.
- Night 2 has a default Bùa Gió at (35,0,0) on the bridge; scenarios that walk over it must pass `charms: []`.

## Constraints that shape the code

- **Test Contract / headless mode**: each phase defines a fixed-format headless run (fixed input and output) that hidden graders run against each tag. Read it before designing the architecture. Keep game logic separate from rendering so it runs without a window, and deterministic (same input gives the same output). Re-run old scenarios whenever the contract changes.
- **Graded at each tag**: graders check out each `phase-N` tag in a clean clone and follow the README, which must allow install and run in at most 3 commands. Evidence (tests, headless output, screenshots, measurements) must match the code at that tag.
- **Test integrity**: never write tests that always pass or hand-edit program output to match expectations (a serious violation). If a later phase invalidates an old test, fix or remove it and record why. Mark unmet requirements "chưa đạt" with the reason.
- **Git**: do not rewrite history or force-push after tagging. Do not delete harness files (AGENTS.md/CLAUDE.md, skills, hooks, MCP config). Commit small, one change per commit.
- **Assets and secrets**: characters and setting are original to the lab, so don't use existing game or film IP. External assets must be CC0/CC-BY/MIT or self-made/AI-made, and credited in `CREDITS.md`, along with a `LICENSE`. Never commit `.env`, API keys or tokens.
- **Required in the final repo**: the README starts with the demo video link (`.mp4` under 5 minutes, attached to the Release or at `docs/demo/demo.mp4`). The repo also needs per-phase assumptions, an AI usage log with token/cost estimates, and a retro. The suggested layout is `docs/notes/`, `docs/proof/` and `docs/demo/`.
- **Scope**: correctness against stated requirements beats polish. Extra creativity is scored only under rubric F and must not break requirements. Record it in a "Sáng tạo của tôi" section of the project README.
- **Repo naming** for submission: `K5-<L3A|L3B>-DAY12-<HoVaTen>-<MSSV>-AI-SDLC-Dao-Den-Long`, public.

## Working style the lab rewards

Per phase: write short acceptance criteria and note assumptions for ambiguous points, plan how to verify before coding, build in small steps, verify by actually running (not by trusting agent claims), then tag. Keep this file short, and update it when the agent repeats the same mistake.
